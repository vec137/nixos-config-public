# Приёмка отчёта глазами придирчивого преподавателя

Порядок жёсткий: сначала механика и сверка, потом чтение. Чтение «по памяти»
без извлечения первоисточника — главный источник пропусков: вопрос методички
остаётся без ответа, потому что в отчёте на его месте стоит переформулировка
другого вопроса.

## Шаг 1. Извлечь первоисточник и отчёт в текст

```bash
python3 scripts/extract_docx_text.py "задание.docx" > /tmp/rev/task.txt
python3 scripts/extract_docx_text.py "Отчёт.docx"   > /tmp/rev/report.txt
```

Дальше работать с этими файлами, а не с Word'ом: дифф, grep, короткие вызовы
модели к фрагментам. В контекст агента не тащить ни методичку целиком, ни
отчёт целиком — только выгрузку пар/фрагментов.

## Шаг 2. Покрытие вопросов

```bash
python3 scripts/qa_coverage.py ЗАДАНИЕ1.docx ЗАДАНИЕ2.docx ЗАДАНИЕ3.docx -- Отчёт.docx
```

Передать нужно **все** документы заданий, из которых собран отчёт: если подать
только часть, второй список («вопросы отчёта не найденные в задании») наполнится
ложными срабатываниями — вопросы из непрошедших документов будут выглядеть
выдуманными.

Три списка на выходе:
- **задание без ответа** — проверять вручную: половина оказывается ложным
  срабатыванием (ответ есть, но переформулирован);
- **вопрос отчёта, которого нет в задании** — частый признак выдуманного вопроса
  или, наоборот, того, что инструкцию («Сохраните пароль.») оформили как вопрос;
- **пустые ответы / непроцитированные рисунки и таблицы**.

Порог fuzzy 0.55 щедрый намеренно: инструмент сужает круг проверки, вердикт
за человеком.

## Шаг 3. Подпись ↔ кадр (самое провальное место)

Человек (и модель) читает подпись и верит ей. Проверяется только смотрением на
сам кадр — пачками, через монтажи:

```bash
python3 scripts/caption_montage.py --from-generator generate_report.js \
        --shots screenshots --out /tmp/mont
```

Получаются листы по 12 кадров (3 колонки, подпись в 2 строки), каждый с номером
(== номер рисунка в отчёте) и ожидаемой подписью. Смотреть и отвечать на один
вопрос: «то, что на экране, соответствует подписи?». Типичные находки:
- кадр подписан «эхозапрос к H4», а на нём локальный пинг до шлюза;
- в подписи «(TTL=63)», а кадр — терминал `ping`, где TTL не виден;
- в тексте «в пике 56 строк (рис. 8)», а на рис. 8 — 38 строк;
- кадры местами, дубли, чужое окно, следы автоматизации (команды `xdotool`,
  скрипты, приглашение root вместо ожидаемого пользователя).

## Шаг 4. Числа

Каждое число в тексте обязано быть прослеживаемо: либо оно видно на конкретном
кадре, либо оно из журнала замеров. Если ни там ни там — в тексте должно стоять
«—» с пометкой, что требуется замер/пересъёмка. Проверка:

```bash
grep -oE '[0-9]{2,}([.,:][0-9a-fA-F.]+)*' /tmp/rev/report.txt | sort -u > /tmp/rev/nums.txt
grep -f /tmp/rev/nums.txt журнал_замеров.md   # и наоборот: чего нет в журнале
```

Часовая ошибка этого класса: «время подбора 3 ч 00 мин 59 с (рис. 15)» — число
есть в журнале замеров, но в кадр не попало; ссылка на рисунок вела в никуда.

## Шаг 5. Четыре класса ошибок в формулировках (чек-лист критика)

Гонять изолированными короткими вызовами модели по 5–10 пар вопрос→ответ,
каждый вызов — со своим чистым контекстом и этим чек-листом:

1. **лишние сущности** — в ответе то, чего в задании не спрашивали и чем не
   подтвердить (назвал протокол, которого нет на кадре);
2. **не те единицы/направление** — пять элементов сеанса в обратную сторону
   (взяты из строки оповещения, где показан ответ), TTL запроса вместо TTL
   ответа, байты вместо пакетов;
3. **протечка инструмента** — вывод/аргументы инструмента, которым мерили,
   попали в текст или в кадр там, где их быть не должно;
4. **оговорка про расхождение** — «примерно», «порядка», «совпадает» без
   основания; «побайтно совпадает», хотя на кадре нет сравнения файлов.

Плюс фактические ошибки определений (отпечаток сертификата «подписан
издателем» — отпечаток никто не подписывает) и кальки машинного перевода из
методички, повторённые авторским текстом («трёхстороннее квитирование»,
«хорошо известный порт», «служебная программа»).

## Шаг 6. Лишние вставки

Искать многострочные цитаты вывода команд в тексте отчёта — они дублируют
кадр, под которым стоят:

```bash
grep -n 'para("[^"]*\\n' generate_report.js     # генератор на Node
grep -nE '^[0-9]{2}:[0-9]{2}:[0-9]{2}\.' report.txt   # вывод tcpdump-подобного формата
```

## Шаг 7. Оформление

Нумерация, цитирование каждого рисунка/таблицы, разрывы таблиц, оторванные
подписи, пустоты — скилл `pdf-layout-acceptance` (плюс `docx-report-pipeline`,
если правки идут в генератор).

## Фиксация результатов

По каждому документу — `TODO.md` рядом с отчётом: что найдено, что исправлено
в тексте, что требует пересъёмки/перезамера (с указанием, почему пересъёмка
невозможна, если невозможна). Раздел приёмки дописывается датой — следующая
проверка начинается с него, а не с нуля.
