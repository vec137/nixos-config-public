# Приёмка PDF механическими проверками

Глаза модельки/человека такие дефекты не видят: страница выглядит «нормально»,
а подпись висит в начале следующей. Поэтому — скрипты, а не просмотр.

```bash
soffice --headless --convert-to pdf --outdir /tmp/out "Отчёт.docx"
python3 scripts/check_captions.py /tmp/out/Отчёт.pdf   # подписи рисунков
python3 scripts/check_report.py  "Отчёт.docx"          # структура docx
```

## 1. Подпись рисунка без рисунка над ней (`check_captions.py`)

Ловушка, из-за которой первая версия проверки врала: `pdftotext` **не видит
картинки**. Если просто искать «Рисунок N.» в начале страницы, ложноположительных
ответов больше, чем реальных: рисунок на той же странице, просто текста над
подписью нет.

Рабочая схема:
1. `pdftotext -bbox` даёт координаты строк текста (`<word xMin yMin …>`);
2. `pdftoppm -r 72` рендерит страницу в PNG, где **1 pt = 1 px** — координаты
   из bbox становятся пиксельными;
3. для каждой строки, начинающейся с «Рисунок N», проверяется полоска над ней
   (от конца предыдущей текстовой строки до начала подписи): если она
   однотонная (`magick … -format "%[standard-deviation]"` ≈ 0) — рисунка над
   подписью нет, это отрыв.

Лечение в генераторе — `keepNext: true` у параграфа с картинкой (см. скилл
`docx-report-pipeline`). После лечения пересчитать число страниц: `keepNext`
обычно добавляет 1–3 страницы, это нормально.

## 2. Разорванная таблица

```bash
pdftotext -layout /tmp/out/Отчёт.pdf - | grep -nE 'ЗаголовокШапки|ПодписьСтроки'
```

Заголовок и первая строка данных должны быть на одной странице (одна страница в
выводе `pdftotext -layout` — один блок). Если разъехались — в генераторе
`cantSplit: true` у всех строк, `tableHeader: true` у шапки, `keepNext: true` у
абзацев всех строк кроме последней. Перенос текста внутри ячейки лечится
подбором ширины колонки, а не переносом.

## 3. Пустоты и пустые страницы

```bash
pdftotext -r 72 … # либо попиксельно:
for f in pg-*.png; do geo=$(magick "$f" -fuzz 3% -trim -format "%X %Y %w %h" info:)
  set -- $geo; awk -v y="$2" -v h="$4" 'BEGIN{b=842-(y+h); if(b>120) printf "пустота внизу %.0f pt\n", b}'; done
```

>120 pt (~4 см) пустого низа на не-последней странице — повод посмотреть кадр.
Полностью белая страница — дефект почти всегда.

## 4. Содержимое docx (`check_report.py`)

Проверяет без рендера: плейсхолдеры (`@@FILL`, `_____`, «Вписать»), наличие
оглавления/источников (если по стилю их быть не должно), сплошную нумерацию
рисунков и таблиц, **цитирование каждого рисунка и таблицы** в тексте (понимает
диапазоны «рис. 5–7» и перечисления «рис. 22, 23 и 24»), совпадение встроенных
изображений с файлами из каталога кадров (побайтово), `cantSplit` у строк
таблиц, число страниц. Выход ≠ 0 — документ не готов.

Именно этот чекер нашёл 19 рисунков без ссылок в тексте там, где ручной
`grep 'рис. [0-9]'` ничего не заподозрил.

## 5. Быстрые grep-инварианты по исходнику

```bash
grep -c '—' generate_report.js          # запрещённое длинное тире (если стиль «–»)
grep -cE 'Вопрос\s+[0-9]+\s*\.' out.txt # счёт вопросов
grep -n '@@FILL\|_____\|Вписать' out.txt # должно быть пусто
```

## Порядок, в котором это имеет смысл

сначала механика (этот скилл) → потом содержательная вычитка текста. Обратный
порядок означает перечитать документ дважды: правка нумерации меняетpagination и
возвращает дефекты вёрстки.
