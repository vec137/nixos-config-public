# Грабли съёмки с ВМ (проверено на практике)

## Захват

| Симптом | Причина / решение |
|---|---|
| `xwd -id <окно>` даёт кадр из двух цветов | `xwd` читает пиксели рамки WM, а не окна-ребёнка. Снимать с хоста: `VBoxManage controlvm <ВМ> screenshotpng`, затем кроп |
| обрезка срезает 1–2 строки сверху/снизу, уезжает вправо-вниз | координаты взяты из `xdotool getwindowgeometry` (смещены на толщину рамки). Брать `xwininfo` + `_NET_FRAME_EXTENTS` |
| в кадр попало чужое окно / кадр 10×10 | `xdotool search --name` матчит несколько окон, среди них заглушки. Выбирать самое большое по площади (`winpick.sh`) |
| `xdotool type` ввёл половину символов | фокус ушёл (всплывающее окно браузера/диалог). Перед каждым вводом `windowactivate --sync` + `windowraise` |
| `xdotool windowmaximize` — «Unknown command» | в старых xdotool нет этой подкоманды; `windowmove` + `windowsize`, либо `key super+Up` |
| `xdotool windowclose` закрыл всё приложение | у однооконного Firefox закрытие единственного окна убивает процесс. Для вкладок — `key ctrl+w` |
| `xdotool getwindowname`/`search` не находят окно | окно ещё не перерисовалось; ждать 20–30 с после запуска GUI |

## Терминальные кадры

- **xterm: белый фон, чёрный текст.** Обрезать по содержимому, иначе под
  подписью в PDF висит белая дырка:
  ```bash
  magick in.png -crop WxH+X+Y +repage b.png
  geo=$(magick b.png -fuzz 8% -trim -format "%X %Y %w %h" info:)
  magick b.png -crop Wx(Y+h+12)+0+0 +repage out.png
  ```
- **xfce4-terminal: тёмный фон.** Так его не обрезать — `-trim` по белому
  съест рамку. Пустой низ режет `crop.sh` по яркости строк.
- Смешивать размеры кадров в одном документе можно (1024×768 Wireshark +
  590×383 терминал), но внутри одной серии держать один размер.

## Гость: команды и окружение

- `sudo` срезает `DISPLAY`/`XAUTHORITY`. Нужны GUI-оболочки из-под CLI
  минисети — запускать топологию как `sudo env DISPLAY=:0 XAUTHORITY=/home/<u>/.Xauthority python2 …`,
  тогда доступно `xterm <УЗЕЛ>` (регистр имени важен: `H3`, не `h3`).
- CLI минисети чувствителен к регистру: `h3 ip link …` → «Unknown command».
- `ifconfig ethA ethB` → «Host name lookup failure»: второй аргумент воспринимается
  как алиас интерфейса. Либо два вызова, либо `ifconfig -a` в окне повыше.
- `pkill -f firefox` убивает собственную SSH-сессию (паттерн матчится по своей
  командной строке). Правильно: `pkill -x firefox`.
- SSH в госте деградирует после запуска минисети: вызов по 120 с, иногда виснет.
  Батчить команды в один вызов, съёмку вести с хоста.
- Выключение: `printf 'password\n' | sudo -S poweroff` по SSH — надёжнее, чем
  `VBoxManage controlvm acpipowerbutton` (иногда игнорируется гостем).

## Приложения

- Wireshark 2.6: `Ctrl+E` (Restart Capture) не возобновляет захват, если Wireshark
  запущен с `-k -i <интерфейс>`. Решение: Escape + второй экземпляр Wireshark.
- FTP в активном режиме через NAT стенда: «Illegal PORT command». В клиенте
  `passive`.
- Cloudflare-сайты из гостя: 403 или пустая страница (старый Firefox не решает
  челлендж). Работает web.archive.org — сниматься с архива и в подписи/тексте
  честно указывать источник и дату снимка.
- Статус-бар Firefox показывает переходящую сетевую активность («Performing a
  TLS handshake to…») — перед съёмкой нажать Escape.
- Поисковый запрос в браузере может не находить нужный источник с первого раза —
  подбирать формулировку, а не вставлять «правильную» картинку из другого места.

## Согласованность с документом

- MAC/порты генерируются заново на каждом запуске эмуляции → закреплять до съёмки
  (`ip link set dev X address …` в CLI минисети), после `down/up` восстанавливать
  маршрут `default via …`.
- Кадры конфигурации самой ВМ на клоне не переснимать: MAC клона
  (`08:00:27:…`) противоречит сентябрьским кадрам. Если старый кадр покрывает
  вопрос — закрыть вопрос без ВМ и записать это в TODO.
- Приёмка кадра двухуровневая: сначала механика (`identify`, stddev, размер),
  потом смысл (то ли окно, нет ли протечки автоматизации). Кадр, не прошедший
  ни один уровень, считается неснятым.
