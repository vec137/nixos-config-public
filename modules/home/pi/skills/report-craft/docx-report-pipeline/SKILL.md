# Word-отчёт из генератора (docx)

Источник истины — **скрипт-генератор**, а не сам .docx. Правки в XML готового
документа теряются при первой же пересборке и не проверяются диффом.

## Каркас генератора

```
<проект>/rus/_report_tools/
  generate_report.js   // единственный редактируемый источник
  build.sh             // node generate_report.js && (опц.) постобработка
  shots/ или screenshots/  // кадры, которые вшивает figure()
```

Обязательные блоки генератора (готовый каркас — `scripts/figure_snippet.js`):

1. `SHOTS` — абсолютный путь к каталогу кадров; номер рисунка считается из
   порядка вызовов `figure()`.
2. `figKey` — пре-скан собственного исходника регуляркой
   `\.\.\.figure\("([^"]+)"` и присвоение номеров **до** сборки.
3. `resolveRefs()` — подмена токенов `{{файл.png}}` / `{{tbl:ключ}}` числом.
4. `figure()` с проверкой `figKey[file] === figNo` — сборка падает, если
   нумерация разъехалась, а не печатает неверный номер.

## Токены вместо литеральных номеров

В тексте пиши `рис. {{s2-01-tcp-handshake.png}}` и `таблица {{ftp-syn}}`,
а не `рис. 12`. Вставка/удаление кадра тогда не сдвигает подписи во всём
документе. Литеральные «рис. N» допустимы только в старых документах, которые
больше не пересобираются; при правке такого документа — сначала перевести на
токены, потом править.

## Три обязательных правила вёрстки

| Дефект | Лечение |
|---|---|
| таблица рвётся через страницу | `cantSplit: true` у **всех** строк, `tableHeader: true` у шапки, `keepNext: true` у абзацев всех строк кроме последней |
| текст переносится внутри ячейки | подбирать ширины колонок (twip) под самую длинную подпись строки |
| подпись рисунка уезжает на следующую страницу | `keepNext: true` у **параграфа с ImageRun** (картинка держит следующую за собой подпись) |

Ширины и `cantSplit` проверяются не глазами, а рендером в PDF — см. скилл
`pdf-layout-acceptance`.

## Сборка

```bash
bash <путь>/_report_tools/build.sh "$PWD/<путь>/Отчёт.docx"   # ПУТЬ ОБЯЗАТЕЛЬНО АБСОЛЮТНЫЙ
```

Относительный путь в аргументе вывода — реальная причина потери файла: скрипт
ищет выход относительно другого каталога и молча пишет не туда. Если build.sh
содержит постобработку (например внедрение оглавления), условие «есть ли
оглавление» должно искать `new TableOfContents`, а не `TableOfContents`:
второе матчится со строкой импорта библиотеки, и постобработка падает на
документе без оглавления.

## Цикл правки (обязателен, а не «на глаз»)

1. поправить `generate_report.js`;
2. пересобрать абсолютным путём;
3. `python3 scripts/check_report.py "<docx>"` — плейсхолдеры, нумерация и
   цитирование каждого рисунка/таблицы, совпадение вложений со скриншотами,
   `cantSplit`, число страниц (выход ≠ 0 — документ не готов);
4. `soffice --headless --convert-to pdf` и `pdf-layout-acceptance` — подписи,
   разрывы таблиц, пустоты;
5. только потом — содержательная вычитка текста.

Механические проверки ловят то, что не видит ручной grep: в одном отчёте 19
рисунков остались без ссылок в тексте, хотя `grep 'рис. [0-9]'` выглядел
спокойно (чекер понимает диапазоны «рис. 5–7» и перечисления «рис. 22, 23 и 24»).

## Что проверять дополнительно перед сдачей

```bash
grep -c '—' generate_report.js            # длинное тире в авторском тексте (если стиль — «–»)
grep -cE 'Вопрос\s+[0-9]+\s*\.' out.txt   # нумерация вопросов
# в тексте нет: @@FILL, _____, «Вписать», «См. вопросы задания.»
```

Кальки машинного перевода из исходных методичек в авторском тексте не
повторять: «трёхстороннее квитирование» → «рукопожатие», «хорошо известный
порт» → «общедоступный», «служебная программа» → «утилита», «файл сбора» →
«файл захвата», «сеанс TCP» → «соединение TCP». Дословные цитаты заданий и
вопросов первоисточника остаются как в оригинале — их не править.

## Рендер и раскладка

```bash
soffice --headless --convert-to pdf --outdir /tmp/out "Отчёт.docx"
pdftotext -layout /tmp/out/Отчёт.pdf - | grep -nE 'Заголовок шапки|подпись строки'
```

Заголовок таблицы и её данные должны оказаться на одной странице. Дальше —
скилл `pdf-layout-acceptance`.
