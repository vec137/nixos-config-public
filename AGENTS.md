# AGENTS.md

Правила этого репозитория живут в `CLAUDE.md` (команды, VPS-туннель `ru-edge`/
`nl-exit`, конвенции, куда что писать) и в `docs/repo-notes.md` (архитектура,
состояние хостов, грабли, открытые задачи). Оба файла — источник правды и для
остальных агентов тоже; если в сессии прочитан только этот файл, прочитай их
перед тем, как трогать что-то нетривиальное.

Здесь только то, что отличается для pi (и вообще для агентов, читающих
`AGENTS.md`):

- **Правки — в git worktree, не в основном чекауте** (то же, что в
  `CLAUDE.md` для Claude; полное правило — в `modules/home/pi/AGENTS.md`,
  он симлинком лежит в `~/.pi/agent/AGENTS.md`):

  ```
  git -C /home/nix/.nix worktree add /home/nix/.nix/.pi/worktrees/<имя> -b pi-<имя>
  ```

  Правки, коммиты и `nix build` — внутри worktree абсолютными путями;
  в основном чекауте только `git merge --ff-only pi-<имя>`, push и
  `git worktree remove`. Каталоги worktree игнорируются
  (`/.pi/worktrees/` в `.gitignore`), чтобы не конфликтовать с
  Claude-овскими `.claude/worktrees/`.
  Грабля: gitignored `ssh/`, `xray/`, `misc/` в worktree нет. В оценке
  флейка они не участвуют (в `programs.ssh` это рантайм-пути
  пользователя, а не store-пути), поэтому `nix build …toplevel` из
  worktree проходит — проверено. Если задача всё-таки требует этих
  файлов, работать в основном чекауте и сказать пользователю.
- **Коммиты — под автором `pi`, не `Claude`.** Claude правит этот репозиторий
  по своему `CLAUDE.md` и коммитит под собой; наши коммиты должны отличаться и
  от его, и от пользовательских. Без правки git config:

  ```
  git -c user.name="pi" -c user.email="pi@noreply.local" commit -m "..."
  ```

  После коммита — push.
- Сообщения коммитов: `type(scope): summary`, нестрого.
- Ветку истории не переписывать: уже запушенные коммиты (в том числе под
  автором `Claude`) остаются как есть, force-push не нужен.
- Обновлять `docs/repo-notes.md` по мере появления нестандартных фактов
  (грабли из отладки, объяснённое проектное решение, паттерн, который стоит
  повторить) — не дожидаясь просьбы. Сам этот файл держать коротким, детали —
  там.
